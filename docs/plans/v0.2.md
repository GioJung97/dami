# LocalFlow v0.2 — Implementation plan

**Goal:** a version that can be used all day and be trusted. It never loses speech silently, always says
what happened, and removes obvious fillers with conservative rules. No LLM in this version.

**Principle (from the owner):** ship something usable, then improve across versions. Do not widen the
scope. If something below turns out to be large or wrong, stop and ask rather than expanding it.

Decisions come from the 2026-11-01 review: `docs/sessions/2026-11-01-review-and-v0.2-scope.md`.

---

## 1. Decided

| Topic | Decision |
|---|---|
| Version split | v0.2 = this plan. v0.3 = edit capture and word suggestions first, then LLM if measurements justify it (§7) |
| Paste into a different app after switching during processing | **Not changing.** The owner expects users to look at the output first. Listed under "later" |
| Recording limit | **5 minutes** in every mode. Warn at 4:00. At 5:00 stop and transcribe; nothing is discarded (owner, 2026-11-04, after trying 10 minutes: longer than needed) |
| Microphone | Follow the macOS default by default, manual choice in Settings and the menu, **no popups**, one short HUD note for Bluetooth |
| Text history | Default retention becomes **Forever**. Delete options stay |
| Saved audio | Still off by default. When on: 7 / 30 / 90 days, default 30, separate from text. Show disk usage. No size-based limit |
| Self-correction rules | Numbers and times only |
| Dictionary | Keep it. Make the copy match what it really does (M7) |
| Unfinished UI ("Coming later" cards) | Leave as is. Not a defect at this stage |
| Eval clips (`bench/clips/`) | Not needed for v0.2. They are on another Mac and move over when preparing v0.3 |

## 2. Out of scope

Do not build these in v0.2: LLM or Smart mode, edit capture and suggestions, focused-field context for a
prompt, focus-change protection on paste, microphone ranking, size-based storage limits, merging Vocabulary
and Replacements, Korean vocabulary in the Whisper prompt, hardware-based model choice, per-app modes,
sync, `.dmg` / `release.sh` / notarization, CI, Whisper fine-tuning.

### M1 — `LocalFlowCore` package and tests

Create a local Swift package at `LocalFlowCore/` (added to `project.yml` under `packages:` with `path:`, and
as a dependency of the app target). No AppKit, WhisperKit or GRDB in it. Use XCTest. Toolchain here: Xcode 16.4.

Move in (pure logic only):
- `ReplacementEngine` (`Personalization/Replacements.swift`), using a small plain rule type in Core. The GRDB
  record stays in the app and maps to it.
- `HallucinationFilter`.
- `SpokenLanguage` and `Script`.
- New `TextPipeline`: `process(raw:mode:language:rules:) -> ProcessedText` with the stage outputs. In M1 it only
  runs Replacements; M6 adds rules.
- New `PromptLeak.isLeak(output:prompt:vocabulary:)`: Whisper can echo its prompt on noise. Treat a transcript
  as hallucination if it essentially is the mixed prompt or just the vocabulary list.
- A small executable target `localflow-eval` (used in M6).

**Done when:** `swift test --package-path LocalFlowCore` passes with tests for replacements (word boundaries,
Korean particle after a Latin term such as "Cloud Code로", longest rule first), the hallucination list, prompt
leaks and script detection; the app behaves the same as before.

### M2 — Audio reliability and microphone choice

Files: `Core/AudioRecorder.swift`, settings, menu.

1. **Tap leak.** `start()` installs the tap and then `engine.start()` can throw (`AudioRecorder.swift:27-31`),
   leaving a tap whose duplicate raises an exception on the next attempt. Remove the tap on every failure path.
2. **Engine freshness.** Observe `AVAudioEngineConfigurationChange`. Prefer a new `AVAudioEngine` per recording
   if start latency stays acceptable (measure it); a cached format after a device change can crash `installTap`.
3. **Device lost mid-recording.** Keep what was captured, transcribe it, and report it (M4). The next recording
   uses the new device.
4. **Off the main thread.** Engine start can block, particularly on Bluetooth, and the main thread currently also
   runs the event tap. Start it on a serial queue; `stop` must wait for any start in progress.
5. **Permission check** before starting: report a missing microphone permission instead of recording silence.
6. **Tail capture.** Keep recording about 200 ms after release so last syllables survive (constant, tune by ear).
   Not on discard or cancel. A new press during the tail ends the tail at once and starts the new recording.
7. **Recording limit.** Constants: warn at 240 s, stop at 300 s, both modes. Stopping goes through the normal
   finish path. Releasing a key afterwards must do nothing, and the still-held key must not start a new recording.
8. **Sleep.** On `NSWorkspace.willSleepNotification` while recording, finish the recording.

**Microphone choice**
- Setting `inputDeviceUID: String?`, nil meaning "System default". Show it in Settings → General and in the menu.
- Enumerate input devices with Core Audio. Select with `kAudioOutputUnitProperty_CurrentDevice` on the input node's
  audio unit. Match saved devices by UID.
- Hide virtual and aggregate devices from the list (this Mac has "Microsoft Teams Audio") unless already selected.
- Chosen device missing: use the system default and say so once in the HUD. Don't change the saved choice. The picker shows
  the system default while it's missing and returns to the chosen device when it's back, with a one-time "Using <mic>" note on the next recording (owner, 2026-11-04).
- Bluetooth or Continuity (iPhone) as active input: one HUD note per connection that the first words may be cut.
  Use the device transport type. No popups, no automatic switching logic of our own.

**Manual test (owner):** AirPods connect/disconnect between recordings and during one; unplug a USB mic; pick a
device in the menu; start a recording with mic permission off; hold for over 9 minutes; close the lid while recording.

### M3 — Controller split, queue, event tap thread

**Split `DictationController`** (285 lines) into:
- Hotkey and recording state, still published for UI.
- A serial `DictationQueue`: transcribe → `TextPipeline` → paste → record. Each job owns its audio, options and
  app info.

**Queue behaviour**
- Pressing the shortcut while a dictation is processing starts a new recording instead of being ignored
  (`DictationController.swift:142`). Results are handled strictly in order.
- **Paste only when no recording is active.** Results that finish during a recording wait until it ends.
- Esc: during recording it cancels the recording. With no recording but work in flight, it cancels all pending
  jobs. WhisperKit checks cancellation cooperatively, so a discarded job may keep running briefly; its result must
  be ignored.
- Escape is swallowed only in those two situations.

**Self-inflicted cancel (important).** The tap sees our own synthetic ⌘V. In modifier-only mode a `keyDown` while
`held` fires `onCancel` (`HotkeyMonitor.swift:83-87`), so once pastes can happen near a recording they could cancel
it. Tag synthetic events with `eventSourceUserData` and ignore them in the tap. The "paste only when no recording
is active" rule above is also required, not optional.

**Event tap thread**
- Run the tap on a dedicated thread with its own run loop. Today every keystroke on the machine passes through
  LocalFlow's main thread, so any UI or database stall delays typing everywhere.
- `shortcut`, `isRecording`, `isSuspended` and `held` then cross threads: protect them with a lock
  (`OSAllocatedUnfairLock`). Handlers keep dispatching to main.
- **Missed key-up.** When the tap was disabled by timeout, re-enable it and compare the current modifier state
  (`CGEventSource.flagsState`, verify it reports device-specific bits). If the shortcut is no longer held, fire
  release, so a recording can't be left running.

**Manual test:** speak a second sentence immediately after the first; both arrive in order. Dictate while the first
is processing and confirm the recording isn't cancelled. Esc while processing. Type at full speed in another app
while scrolling a long History.

### M4 — User-facing states and recovery

Principle: long work is announced; failure gives a reason and a next step; audio isn't thrown away.

**HUD changes:** add a message phase with text and an optional action. The panel is 220 × 44 and ignores the mouse
(`HUDController.swift:76`, `:97`), so make it wider and accept clicks **only** while showing an action. It must stay
non-activating. Keep English UI strings.

| Situation | Behaviour | HUD text (draft) |
|---|---|---|
| Shortcut while model **loading** (after launch) | **Record anyway**; the job waits for the model | "Getting ready…" after release |
| Shortcut while model **downloading** | Don't record | "Downloading speech model · 43%" |
| Download failed | Reason + Retry, in onboarding and Settings → Models. Check free space first | "No internet connection" / "Not enough disk space" + Retry |
| Model load failed or files bad | Offer re-download | "Speech model couldn't load" + Re-download |
| Shortcut while model unavailable | Don't record | "Speech model isn't ready" + Open |
| Dictations waiting | Show count | "Processing · 1 waiting" |
| Processing over 5 s | Keep going | "Still working… Esc to cancel" |
| Processing over max(30 s, audio length) | Cancel the job, keep audio | "Took too long" + Retry |
| Transcription failed | Keep audio | "Couldn't transcribe" + Retry |
| Language detection failed | **No error.** Fall back to Whisper's own detection, no prompt | – |
| Silent recording | Nothing pasted | "No sound heard · Mic: MacBook Air" |
| Silent twice in a row | Offer mic settings | adds "Check microphone" action |
| Hallucination or empty | Nothing pasted | "No speech recognized" |
| Very short tap | Stays silent. It's also half of a double-tap | – |
| Mic permission missing | Open the settings pane | "Microphone permission needed" + Open |
| Accessibility missing at paste | Copy instead | "Copied · press ⌘V (Accessibility is off)" |
| Password field | Copy | "Password field · Copied, press ⌘V" |
| No text field | Copy | "No text field · Copied, press ⌘V" |
| Mic lost while recording | Transcribe what exists | "Microphone disconnected · kept what you said" |
| Recording at 4:00 / 5:00 | Warn / stop and transcribe | "1 minute left" / "5 minute limit reached" |

Timings are first guesses, kept as named constants.

**Failure and retry**
- Hold up to 3 failed jobs (audio and options) **in memory only**, until retried, dismissed or the app quits. Add a
  "Failed dictation · Retry" row to the menu. A retry pastes at the current cursor.

**Model state fixes**
- `isModelReady` returns true for `.failed` (`DictationController.swift:63-68`), so onboarding shows "Ready" and
  lets you continue after a failed download (`OnboardingView.swift:191-211`). Separate transient failure from model
  failure; the Continue button must stay disabled until the model really is ready.
- Add a retry path; today only restarting the app helps.
- `isModelDownloaded` checks only `AudioEncoder.mlmodelc` (`Transcriber.swift:43-45`), so an interrupted download can
  look complete and fail forever. Require all of `AudioEncoder`, `MelSpectrogram`, `TextDecoder`,
  `TextDecoderContextPrefill` (`.mlmodelc`), `config.json`, `generation_config.json`.
- A transient failure must not block new recordings (`DictationController.swift:142`, `:278`). A failed job shouldn't
  stop the next one.
- Replace "Picked for this Mac" (`OnboardingView.swift:134`); nothing picks a model yet. Show the Mac's description
  neutrally.

**Manual test:** Wi-Fi off and model folder moved away, then launch. Interrupt a download. Dictate right after launch.
Force a transcription error with a temporary debug switch and retry it. Check each row in the table you can reach and
list the rest for the owner.

### M5 — Insertion quality

File: `Insertion/TextInserter.swift`; the decision logic belongs in Core and is unit-tested.

**Spacing between dictations.** Text is trimmed before pasting (`Transcriber.swift:163`), so consecutive dictations
join: "I went home.Then I ate."
- Read the character before the caret with Accessibility (`kAXSelectedTextRangeAttribute` and
  `kAXStringForRangeParameterizedAttribute`, or the value).
- Prefix one space when that character is not whitespace or an opening bracket/quote, and the new text doesn't
  start with closing punctuation.
- No spaces for languages that don't use them: add `usesSpaces` to `SpokenLanguage`, false for ja and zh.
- **If Accessibility can't read the field** (terminals like cmux, which is most of the owner's use today, and some
  Electron apps): prefix a space only if the previous dictation went into the same app, in the last 2 minutes, and
  **no key has been pressed since**. The event tap may record that a key was pressed as a single flag. Never store
  which key. Otherwise no prefix.

**Clipboard managers.** On the temporary paste write, also set `org.nspasteboard.TransientType` and
`org.nspasteboard.AutoGeneratedType`, so dictated text stays out of clipboard histories. The copy-only path stays a
normal copy, since the user wants it there.

**Manual test matrix:** two dictations in a row, and one after moving the caret, in Notes, Slack, Chrome, VS Code,
Terminal and cmux; also with Maccy or Raycast clipboard history if available. Record the results in the session note.

### M6 — Cleanup rules, modes, eval set

**Pipeline (Light):** Whisper raw → Replacements → rules → final.
**Raw mode:** exactly what Whisper wrote: no Replacements, no rules. Default is **Light**.
Mode control in the menu and Settings → General.

**Which rule sets apply** (matters: German "er" means "he", Portuguese "um" means "a"):

| Detected language | Rule sets |
|---|---|
| `en` | English |
| Second language with its own script, e.g. `ko` | English, plus that language's rules (mixed sentences) |
| Latin-script second language (es, fr, de, pt, vi) | **None** |

Only English and Korean have rule sets in v0.2.

**Rules, deliberately narrow.** A filler left behind is fine; a changed meaning is not.

| Rule | Removes | Must not touch |
|---|---|---|
| English fillers | standalone `um, umm, uh, uhh, er, erm, hmm, mm`, with their commas; recapitalize after a sentence-initial removal | `ah`, `like`, `so`, `you know`, `I mean`; words containing a filler ("summer"); all-caps `ER` ("the ER doctor") |
| Korean fillers | standalone `음`, `으음`, including `음...`, only at a sentence start or next to a comma or ellipsis, since `음` is also a noun ("이 음 좋다") (owner's call, 2026-11-02) | `어`, `아` ("어, 맞아"), `그`, `이제`, `막`, `약간`, `뭐`, words containing 음 ("음악", "다음") |
| Repeated words | adjacent duplicates from an allowlist only. en: `a an the i to of in on at and or but is it`. ko: `그 이 저` | "that that", "had had", "very very", "bye bye", "네 네", "그래 그래", "진짜 진짜" |
| Number self-correction | `X, MARKER Y` where X and Y are both tokens starting with a digit, same sentence. Markers: `no`, `no actually`, `actually`, `wait`, `sorry`, `아니`, `아니다`, `아니요` | anything without digits on both sides: "I told him, no, we can't", "맞아, 아니 근데" |

Examples that must pass: "at 3, no, actually 4 p.m." → "at 4 p.m."; "3시에, 아니 4시에 강남역" → "4시에 강남역";
"we should, uh, push" → "we should push"; "Um, I think" → "I think".

**Hallucination check** runs before the pipeline on the raw text, including `PromptLeak`.

**Eval set:** `bench/cleanup_cases.tsv` with columns `id lang category input expected_light notes`.
- `must_fix`: derived from `bench/prompts.tsv`.
- `must_keep`: at least 30 cases that must come through unchanged: the table above; negation (`안 갔어`, "didn't");
  numbers and dates; code identifiers and paths; questions and instructions ("이거 영어로 번역해줘", "What's the
  capital of France?"), which v0.3's LLM also needs; mixed sentences.
- Add an empty `expected_smart` column for v0.3.

`localflow-eval` runs the real `TextPipeline` over the file and writes `bench/cleanup_results.md`.

**Done when:** every `must_keep` passes, `must_fix` results are reported honestly (including ones rules deliberately
don't fix), and rules run in the app. History shows raw vs final, and the note lists what rules changed.

### M7 — Storage: schema v2, retention, query changes, Dictionary copy

**Migration `v2`** on `dictation`, all nullable; old rows stay null:
`mode`, `rulesText`, `rulesApplied` (JSON rule ids), `insertOutcome`, `modelName`, `pipelineVersion`, `inputTransport`,
`wordsJSON`. Everything here must be recorded from now on, since it can't be recovered later. LLM columns wait for
v0.3.

**Word timing (timeboxed spike, half a day at most).** WhisperKit offers `wordTimestamps` with a per-word
probability; v0.3 can use it to tell transcription errors from changes of mind, without saved audio. Measure the
latency cost on fixed audio in Release, using `say`-generated clips through a temporary debug path in the app
(`whisperkit-cli` is not installed on this Mac). If the median increase is
≤ 100 ms, turn it on and store it in `wordsJSON`. If not, leave the column null and note the number. Don't let this
hold up the milestone.

**Retention**
- Text default `Forever`: `retentionDays` falls back to 0 (`AppSettings.swift:75`). An explicitly saved choice is kept.
- New `audioRetentionDays`: 7 / 30 / 90, default 30, shown only when audio saving is on. Show space used.
- `prune` deletes rows but not WAV files (`Store.swift:174-181`). Delete files with their rows; also apply audio
  retention separately from text, and remove orphaned WAVs.
- Prune at launch and every 24 h while running; it currently only runs at launch and on a setting change. The app
  can run for weeks.
- Privacy screen says plainly: text history is stored unencrypted on this Mac until deleted, and audio is only saved
  if turned on.

**Forever needs query changes.** `reload()` loads at most 5000 rows and runs after every write on the main thread
(`Store.swift:138-148`), so older dictations would silently drop out of search and stats.
- Keep a small recent window in memory, with incremental updates rather than a full reload.
- History search and filters use SQL so they reach everything. `languageLabel` is computed in Swift today; for the MIXED filter use `language` plus a `GLOB '*[A-Za-z][A-Za-z]*'` on `finalText`. Escape `%` and `_` in `LIKE` searches.
- Today's stats and streak use SQL. History remains usable with 50,000 synthetic rows; test this with a temporary
  in-memory or scratch database, never the owner's real file.

**"Don't keep" duplicates.** With no saved row, `recent` items all have `id == nil`, and `ForEach` relies on that id
(`Store.swift:6`, `MenuContent.swift:50`), so rows can repeat or map wrongly. Use a wrapper with a UUID.

**Dictionary**
- Keep both Vocabulary and Replacements. Change copy only.
- Placeholders must not suggest Hangul terms work: `DictionaryView.swift:41` and `HistoryView.swift`
  (`AddTermSheet`, "e.g. Supabase, 김지수"). Use English examples.
- Update `DictionaryView.swift:69`: Vocabulary helps English dictations only; for the second language and mixed
  sentences, use Replacements.
- Entering a term in the second language's script shows an inline hint pointing to Replacements. Word it from
  `SpokenLanguage`, not hard-coded Korean.
- Remove the personal seed terms and rules from migration `v1` (`Store.swift:124-133`). GRDB tracks migrations by
  name, so existing databases are unaffected; **verify the owner's existing data stays**.

## 7. v0.3 direction (not part of this work)

Recorded so v0.2 doesn't block it.

1. **Edit capture first.** Lost edits can't be recovered, and real edits are the best evidence on whether an LLM is
   needed. After a paste, briefly re-read the pasted span by Accessibility until it disappears or the app changes;
   store only that span, never surrounding text; never in secure fields. No key logging.
   - Fix in History for apps Accessibility can't read (likely terminals, the owner's most-used app so far).
   - Signal policy: similar-sounding substitution = strongest, especially on a low-confidence word; short deletion and
     punctuation or spacing = cleanup signal; different-meaning replacement = low weight; whole-sentence deletes or
     rewrites and added words = ignored. No edit is only a weak signal.
   - Suggest Dictionary entries after at least 2 repeats; apply only on approval.
2. **Then decide on the LLM.** Copy `bench/clips/`, re-run the Swift pipeline against Phase 0 numbers, measure Korean
   spacing errors (`score.py` ignores spaces, so this has never been measured). If justified: local Qwen3-1.7B with
