# LocalFlow v0.3 — Implementation plan

**Status: plan agreed, 2026-11-04. Don't start until v0.2 is finished.**

**Goal:** LocalFlow learns from fixes the user makes, and turns them into Dictionary and Replacement entries the user approves. This
version only does that. The LLM is v0.4, and evaluation and tuning wait until after v1.0 (`PLAN.md` Roadmap).

**Principle (from the owner):** ship something usable, then improve across versions. Do not widen the scope.

**Who it's for (owner, 2026-11-04):** the owner is the first user and tester, and the design stays general. The owner's usage
numbers, such as the share of terminal or Korean dictations, are one person's sample: hypotheses, never the reason for a design
decision. Before a public release, a few other people try it with consent.

Starts after v0.2's conditions in `CLAUDE.md` are met. Background: `docs/plans/v0.2.md` §7, `PLAN.md` §4.2 and §5. Revised after a
project director's review and the owner's roadmap decisions on 2026-11-04.

---

## 1. What "learning" means here

Whisper's weights don't change in v0.3. Learning happens around the model.

| Level | What it does | Data needed | Version |
|---|---|---|---|
| 1. Dictionary and Replacement suggestions | Fixes repeated words | Fixes | **v0.3** |
| 2. Past corrections as LLM examples | Matches how the user writes | Fixes, an LLM | v0.4 or later |
| 3. Whisper fine-tuning | Adapts to the voice | Audio paired with correct text, hours of it | Later, a separate project |

v0.3 builds level 1 and collects data for levels 2 and 3, so that nothing has to be collected again.

## 2. Decisions

**Decided (owner, 2026-11-04)**

- **When automatic capture gets built, if M1 supports it:** after v0.2 is finished, so it doesn't mix with the week of stability use.
- **On by default,** with a switch in Privacy. It stays on this Mac and only keeps the pasted span. For an open-source release, ask in
  onboarding.
- **How long it watches a paste:** to start, until the app or field changes, the next dictation, or 2 minutes. Log why watching ended,
  and adjust from that.
- **Order:** M1, then M3, M4. M2 is decided from M1's results.
- **"This is what I said":** one action marks the text as a correct transcript and keeps the audio until removed. Only marked clips
  outlast retention, so "90 days" keeps its meaning. Editing alone doesn't keep audio, since people also reword.
- **Very short dictations and the eval tool** moved to after v1.0 (§7). If they turn out to lose speech, they get fixed right away.
- **Eval labels** come from that action, so no agent reads dictations.

## 3. Out of scope

Key logging of any kind. Network use. Whisper fine-tuning. Automatic Dictionary changes without approval. Phonetic comparison between
Hangul and Latin. Silence detection in hands-free, model choice, Command mode, streaming, sync, per-app modes. The LLM (v0.4).

## 4. Rules for fix data

- Keep only the pasted span and what it became, never the text around it.
- Never read secure fields. Check again at every read, since focus can move.
- Discard a result much longer than the original. It's probably not the same text, and could hold something unrelated.
- Keep the raw before and after pair. Signal categories are computed from it, so the policy can change later without losing data.
- Fixes follow the text history setting, and deleting a dictation deletes its fixes.
- Logs and notes never contain dictated or edited text. Agents read numbers only from the real database.
- All audio stays out of git.

### M1 — Spike: what can automatic capture read?

Temporary code that logs numbers only. Report by **kind of app**, not by the owner's usage share: terminal (cmux, Terminal), browser (a
text box, Google Docs), native (Notes), Electron (VS Code).

- Test "caret unknown" and "value unreadable" separately. cmux reports caret 0, but may still expose its text.
- Find the pasted span after a paste, after a real edit, and during Korean IME composition.
- Mouse-only edits. The "a key was pressed" flag can't drive this: reading it clears it, spacing already reads it, and it isn't a
  signal, so capture has to poll.
- Cost of re-reading: time per read, and any lag in very long documents.

**Why it matters:** the owner says they usually fix text in place. If a kind of app is readable, capture sees those fixes at no cost
to the user. If it isn't, Fix in History asks them to fix the same text twice, so few fixes will arrive from that app. **Report this
to the owner before M3.**

**Done when:** a table by kind of app is in the session notes, the temporary code is gone, and the owner has decided on M2.

### M3 — Schema v3, safe migration, Fix in History

**Migration first.** `Store` falls back to an in-memory database on failure with only a log line, and writes use `try?`, so data this
version can't re-collect could vanish silently.
- Back up the file before migrating, and show a warning in the app if the database is unavailable.
- Check the migration on a copy of the real database before building.

**Schema.**
- `edit` table: dictation id (deleted with it), time, source (`auto` or `history`), the text before, the text after.
- A numbers-only row per paste: outcome (edited, unchanged, span lost, unreadable, not watched), why watching ended, time to the edit.
  Without it, "not edited" and "couldn't see" look the same.
- A "this is what I said" mark on the dictation.

**Fix in History.**
- An edit box on a dictation in History, also reachable from the menu's Recent list. The pasted text stays as it was.
- The "This is what I said" action, which keeps the audio until removed. This builds an eval set for later without separate labelling.

**Done when:** the migration keeps all existing data on a copy, a fix is saved as an edit, and a marked clip outlasts retention.

### M4 — Suggestions

- After a fix: **"Always fix this?"**, one click. An explicit fix doesn't need to repeat.
- From automatic capture, if M2 exists: suggest after at least 2 repeats, on a low-probability word. Skip phonetics.
- Applied only on approval. A rejected suggestion doesn't come back.
- **Preview before approval: "this would change N past dictations."** Hangul rules match inside words, so "제안" → "재현" would also
  rewrite "제안서".
- Vocabulary only reaches the prompt for English, so for any second language most suggestions are Replacements.
- **Cap and rank the vocabulary prompt** (moved from the later list). Past 111 tokens the oldest terms drop silently, and learning
  that undoes itself breaks trust.
- A word in the wrong script ("로컬플로우" for "LocalFlow") becomes a Replacement. This is the first answer to the same word coming
  out inconsistently.

**Done when:** a fix produces a suggestion, approving it changes the next dictation, and nothing changes without approval.

### M2 — Automatic capture, if M1 supports it

- After a paste, remember the element and where the span is, then poll until the watching limits in §2.
- Save a fix only if the span was found and differs, and record every outcome in the paste row.
- No effect on paste speed. Off when the setting is off.
- Pure logic in `LocalFlowCore` with tests: finding the span, diff, signal categories.
- Korean diffs: normalize Unicode and trim shared prefixes and suffixes before counting. A word-level diff treats "로컬플로우로" and
  "로컬플로우를" as different words, so repeats never add up.

Signal policy:

| Change | Signal |
|---|---|
| Substitution on a low-probability word, repeated | Strongest |
| Short deletion, punctuation, spacing | Cleanup signal |
| Replacement with a different meaning | Low weight |
| Whole-sentence delete or rewrite, added words | Ignored |
| No edit | Weak signal only |

**Done when:** fixes in readable apps are saved correctly, every paste has an outcome, and the owner sees no slowdown.

## 7. For later

Not in v0.3. Recorded so they aren't lost. Moved here on 2026-11-04: they improve the app rather than build the official version.

### Eval tool that runs the app's pipeline (was M0)

Phase 0 numbers came from `whisperkit-cli`, so the app's real code has never been scored.

- A command that runs clips through the same transcription and cleanup code as the app, with no second copy of the options.
  `Transcriber` imports no AppKit, so a small `LocalFlowSpeech` package is the likely way to share it.
- Scoring: WER for English and CER for Korean as before, plus a **spacing error rate**, which `bench/score.py` has never measured.
- Score raw and final output separately, or removing a filler counts as an error.
- Pin the vocabulary, or scores drift as the Dictionary grows.
- Allow valid Korean spacing variants ("생각해 봐야" and "생각해봐야").
- Break latency down by stage. About 1.1 s of fixed cost on short clips may be the encoder running in detection and again in
  transcription. That's unverified.
- Copy the 30 clips from the other Mac by AirDrop or USB and compare with Phase 0.

**Done when:** the 30 clips have scores from the app's pipeline, with spacing and latency by stage, written to `bench/results.md`. 30
clips show a large regression at most, and can't separate small differences (`PLAN.md` §5).

### Very short dictations (was M5)

Reported by the owner, not yet investigated (`docs/known-issues.md`). In order:

1. Read v0.2's drop counters: reason and length.
2. While Save audio is on, keep the last few dropped clips for a short time. History only holds dictations that survived, so the worst
   cases can't be heard today. Owner listens: is the first sound cut?
3. Through the eval tool, try short clips with and without VAD, with silence padding, and with a language hint instead of detection.
4. Report causes and options to the owner before changing anything. Keeping the mic running to catch the first sound would leave the
   macOS mic indicator on, which is a product decision.

**Done when:** the cause is known with numbers and the owner has picked what to do.

### Other ideas

- **Showing learning:** a repeat-mistake rate, "3 fixes learned, applied 41 times".
- **Low-probability word highlights** in History.
- **Re-dictation detection:** a very similar dictation in the same app soon after suggests the first was wrong. Needs no Accessibility,
  and can run on existing history.
- **Speech accuracy:** mixed-language error was the largest in Phase 0 (11.7% CER). With the eval tool, try prompt and decoder changes before
  assuming an LLM is the answer. If spacing is the only real problem, compare a small spacing corrector.
- **Two Macs:** Dictionary export and import. Learning is per-Mac today.
- **Backups** for Forever history and data that can't be collected again.
- **Release work** is in the `PLAN.md` Roadmap under v1.0.

Dropped from the review, as too much manual work: the owner rating 10 random dictations a week.
